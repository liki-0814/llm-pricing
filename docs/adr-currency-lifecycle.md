# ADR: explicit mixed-currency capability and time-bounded static snapshots

Status: implementation for review, NOT architecture/QA or deployment approval.

## Decisions

1. Keep **api/v1 USD-only** for compatibility (72 current entries, including Qwen4-Max). Add **api/v2** as explicit mixed-currency opt-in (75 entries, including three CNY TokenHub Guangzhou models). Page and interactive docs opt into v2. No FX. Page defaults to USD and filters a single currency; lowest/ranking never combines currencies. SDK price sorting rejects mixed currencies unless filtering to one; each token/media quote carries currency, unit, region and channel. There is no cross-model summing API. Cached unknown prices reject actual usage; unused unknown components are not charged.
2. `data/prices.json` remains the audited source. `assets/availability.js` is the **single lifecycle decision implementation**, called from Node client/browser and Python generator (one batch Node subprocess). Shared `tests/fixtures/lifecycle-cases.json` covers T-1ms/T/T+1ms and equivalent offsets. An exact official instant T retires at `as_of >= T`; current lists/page omit it, identity/routing detail remains explicitly retired with all current rates redacted. A cached pre-T detail is rejected by the updated SDK at/after T; an explicitly historical instant may use a suitable pre-T historical snapshot, never invents a history from a redacted tombstone.
3. Lifecycle evidence preserves raw wording, precision, timezone, scope (`entity` versus `endpoint`), optional routing target, source URLs and conflict. Date-only/unknown/conflicting evidence is pending confirmation, never auto-retired or asserted definitely available. Uncertain availability is surfaced in quotes. Hy4 Preview is date-only; no guessed midnight. No MiniMax auto-retirement or DeepSeek ID migration is added. A routed old ID is not proof the former entity still serves or that old prices apply; detail retains mapping evidence but not current prices.
4. Each build freezes one explicit `as_of` for both API versions and `data/page-models.json`. Metadata includes `source_commit`, `data_version`, `as_of`, `availability_as_of`, and `next_invalidation`. The fingerprint hashes the source with build time/source SHA, so time-dependent output cannot keep an old fingerprint. Checked-in development snapshots have null source_commit; `build_site.py` sets the actual Git SHA in release artifacts. Next invalidation includes exact retirement / offer transitions and the conservative Sol date-uncertainty guard, not a claim of an official unknown cutoff.

## Promotions and estimation scope

- Sol: only correct 11-21 to **11-30**; prices unchanged. Official `until November 30, 2026` lacks time/timezone; no automatic price increase or invented official endpoint. Quotes refuse the uncertainty window beginning when that calendar date could first begin anywhere (UTC+14). This is a conservative estimation guard, NOT an asserted promotion termination time. Existing unrelated legacy date schedules are unchanged.
- Hy4/flash: store **undiscounted directory CNY prices**; precise official until instants are interpreted as inclusive (`at <= until`). At the first instant after the endpoint, official explicit restoration to list price is used. Observation time bounds the supported quote history; it is **not an inferred official promotion start**. No pre-observation historical discount quote. Preview does not inherit a sibling discount. Write-cache '-' remains null/unknown, not zero or not-billed.
- Qwen4: verified Singapore ordinary text input/output only. Cached reads and writes remain unknown and fail on nonzero usage. Mode-dependent limits cannot be collapsed into a fabricated independent output maximum: conservative estimate caps support both modes; full documented mode-dependent limits remain in source notes. Images/video/tool charges are outside this quote.

## Publishing and failure semantics

`build_site.py --output NEW_PATH --as-of ISO` generates a fresh temporary tree, validates source and both complete API contracts, then same-filesystem-renames it to a **new** output directory. It refuses to overwrite a prior release. `--fail-before-publish` exercises failure after validation; no partial output is exposed. A complete Pages artifact is uploaded/deployed, never individual API files. Local generation removes only orphan paths already recorded in each version's `.generated-files` manifest and contained within that generated directory; source data is never deleted. Identity tombstones are deliberately retained.

The proposed Pages workflow serializes publications, rejects a stale main SHA, and rebuilds every 15 minutes (at :07/:22/:37/:52 UTC) plus main pushes/manual runs. **Cron and CDN are best effort, not a precise retirement clock.** Clients must reevaluate lifecycle/offer instants and inspect `as_of`/`next_invalidation`. A failed build keeps the previous complete deployed artifact. Failure is visible in Actions/run summary and `deployment.json.build_url`; no external alert channel is configured or claimed. Before release, confirm GitHub Actions failure notifications/operational ownership. A platform-level deployment failure/concurrency/CDN drill is still required by QA.

The repository was read-only verified to use legacy main/root Pages. **Release coordination must switch Pages to Actions before merging**, avoiding a competing automatic legacy branch build. This PR does not change repository Pages settings, merge, dispatch publication, or deploy. Actions-mode activation and live publication remain release checks. [Official deploy-pages usage/security](https://github.com/actions/deploy-pages#usage) was read this turn; v4 and artifact publication are supported.

## Discovery and unresolved release gates

`scripts/catalog_diff.py` conservatively compares explicit official IDs by vendor/channel, retaining provenance and incomplete coverage. Case folding is safe; punctuation, snapshots, aliases, entities and channels are not silently merged. Alias resolution needs an explicit source-bearing map. Missing prices do not hide new IDs; disappearance never proves retirement. `extract_explicit_ids` supplements damaged merged price tables with explicit invocation labels. This fixed a real local evidence gap: the rerun normalizer had Qwen4 as `api_id_explicit=false` from merged price rows, while its newly fetched detail states the invocation ID explicitly.

The bounded comparison of Sage's fresh snapshots against the old 71-entry baseline detects Qwen4, all three Hy4 IDs and Gemini 3.8 Live, without using those names to limit discovery. This is **not** a full vendor catalog pass, nor a new network run by this implementation. Full enumeration, previous successful directory comparisons, channel classification and lifecycle/alias coverage remain incomplete. Gemini Live necessary conditions and other unverified ID/media candidates are not imported. DeepSeek/Kimi failed current-price reads do not rewrite their old values. PR4 stays separate. Architecture, QA, full-discovery acceptance and production activation are still release gates.
