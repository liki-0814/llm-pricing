公开查询 接口文档

GitHub Pages 无法运行服务端，因此接口以预生成的静态 JSON 文件提供：直接 GET 对应 URL 即可。所有价格为美元 / 每 100 万 token。

基础地址

所有接口位于站点下的 api/v1/。当前页面对应的基础地址：

api/v1/

部署到 GitHub Pages 后通常为 https://<用户名>.github.io/<仓库名>/api/v1/。

接口列表

路径说明
GET/models.json全部模型；meta 含 updated_at、currency、unit、count
GET/models/{model_id}.json单个模型，如 models/deepseek-flash.json
GET/vendors.json全部厂商，含模型数、模型 ID 列表、官方来源
GET/vendors/{vendor}.json单个厂商及其全部模型，如 vendors/openai.json
GET/openapi.jsonOpenAPI 3.1 描述（可导入 Swagger UI / Postman）

静态文件不支持查询参数（如 ?vendor=）——服务器会忽略它们。请取回 models.json 后在客户端筛选、排序。不存在的模型或厂商返回 GitHub Pages 的 404 页面（HTML，而非 JSON）。

数据结构

每个响应都是同一个外层结构：

{
  "api_version": "v1",
  "meta": { "updated_at": "YYYY-MM-DD", "currency": "USD", "unit": "per_1M_tokens", "unit_label": "USD per 1M tokens", "count": 40 },
  "data": [ /* Model[] | Vendor[] | Model */ ]
}

vendors/{vendor}.json 额外包含 vendor 对象；models/{id}.json 的 data 是单个对象，meta 无 count。

稳定性约定：v1 已于 2026-10-11 精简：移除 max_input_tokens、思考模式最大输入/输出等子上限、modalities、features、knowledge_cutoff、thinking_budget、availability、snapshot、aliases；之后 v1 内只会新增字段，不会删除或改名已有字段；价格为 null 时请看 pricing_status 区分“待核实”与“官方未列出”；reasoning_effort、limits 等字段中的 null 一律表示待核实 / 官方未说明，不做推测；pricing_tiers、service_tiers、price_schedule 为空数组表示无或官方未列出。网站上展示的每一项数据（含“详情”展开行）均可在对应模型 JSON 中查询。

跨域与缓存

        
GitHub Pages 默认为所有文件返回 Access-Control-Allow-Origin: *，因此任意网页都可以直接 fetch 这些 JSON，无需代理、无需 _headers 配置（GitHub Pages 也不支持自定义响应头）。

        
GitHub Pages 会对文件设置约 10 分钟的 CDN 缓存（Cache-Control: max-age=600），数据更新后可能需要稍等片刻。数据每次核实后才更新，客户端可按 meta.updated_at 判断是否需要刷新。

      


      

        
数据更新（维护者）

        
接口文件由 scripts/build_api.py 从 data/prices.json 生成，修改数据后务必重新生成：

        
python3 scripts/build_api.py      # 重新生成 api/v1/
python3 scripts/validate.py       # 校验数据，并检查 api/v1/ 与数据是否同步

        
生成结果是确定性的（不含生成时间戳），validate.py 会逐个比对文件，发现缺失、过期或多余文件即报错。
