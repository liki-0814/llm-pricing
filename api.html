公开查询 接口文档

GitHub Pages 无法运行服务端，因此接口以预生成的静态 JSON 文件提供：直接 GET 对应 URL 即可。token 价格为美元 / 每 100 万 token；缓存存储单独按百万 token·小时计价。

基础地址

所有接口位于站点下的 api/v1/。当前页面对应的基础地址：

api/v1/

部署到 GitHub Pages 后通常为 https://<用户名>.github.io/<仓库名>/api/v1/。

接口列表

路径说明
GET/index.json轻量索引：接口路径、模型 ID 和厂商 slug；路径均相对于 api/v1/
GET/models.json全部模型（文本 + 图像 + 视频）；meta 含 updated_at、currency、unit、count、modality_counts
GET/modalities.json模态列表（text / image / video）：各模态模型数、模型 ID 与厂商
GET/modalities/{modality}.json某一模态的全部模型（完整 Model 对象），如 modalities/image.json、modalities/video.json、modalities/text.json
GET/models/{model_id}.json单个模型，如 models/deepseek-flash.json
GET/vendors.json全部厂商，含模型数、模型 ID 列表、官方来源
GET/vendors/{vendor}.json单个厂商及其全部模型，如 vendors/openai.json
GET/openapi.jsonOpenAPI 3.1 描述（可导入 Swagger UI / Postman）

静态文件不支持服务端查询参数（如 ?vendor=）。可直接 GET 单模型 / 单厂商 / 单模态（modalities/image.json），也可用 LLMPrice.createClient 在客户端筛选、排序；先查 index.json 可发现全部 ID。不存在的模型或厂商返回 GitHub Pages 的 404 页面（HTML，而非 JSON）。

数据结构

每个响应都是同一个外层结构：

{
  "api_version": "v1",
  "meta": { "updated_at": "YYYY-MM-DD", "data_version": "源数据 SHA-256", "currency": "USD", "unit": "per_1M_tokens", "unit_label": "USD per 1M tokens", "count": 70, "modality_counts": { "text": 49, "image": 12, "video": 9 } },
  "data": [ /* Model[] | Vendor[] | Model */ ]
}

meta.unit / unit_label 描述文本模型（每 100 万 token）；图像 / 视频模型的计价单位见各自 media_pricing（模型对象的 unit 为 see_media_pricing）。modalities/{modality}.json 额外包含 modality 对象（name、label、model_count、model_ids、vendors、links）；vendors/{vendor}.json 额外包含 vendor 对象；models/{id}.json 的 data 是单个对象，meta 无 count。

cache_pricing.explicit_write_1h / storage_per_1M_tokens_hournumber | null1 小时 TTL 缓存写入价（如 Claude）/ 缓存存储费（每百万 token·小时，如 Gemini），官方列出才有值

reasoning_effort.field_statusobjectsupported/levels/default/can_disable 的字段级状态：verified/unverified/not_applicable。整体存在未核实项时为 partial
meta.data_versionstring源数据内容的 SHA-256；同一快照所有接口一致，可用于识别数据变更
unverified_fieldsstring[]待核实字段列表
links.self / links.vendorstring相对于 api/v1/ 的文件路径
稳定性约定：v1 已于 2026-10-11 精简：移除 max_input_tokens、思考模式最大输入/输出等子上限、modalities、features、knowledge_cutoff、thinking_budget、availability、snapshot、aliases；之后 v1 内只会新增字段，不会删除或改名已有字段；价格为 null 时请看 pricing_status 区分“待核实”与“官方未列出”；推理字段的 null 可能为不适用或待核实，以 field_status 为准；limits 的 null 表示待核实；pricing_tiers、service_tiers、price_schedule 为空数组表示无或官方未列出。参照价格新增 reference 状态；不要将 null 当作零。2026-10-29 新增图像 / 视频模型：新增 modality、media_pricing 字段和 modalities 接口，均为向后兼容的新增；文本模型的原有字段不变。图像 / 视频模型的 pricing.* 为 null（状态 not_applicable），请先按 modality 过滤再读取 pricing，或读取 modalities/text.json。网站上展示的每一项数据（含“详情”展开行）均可在对应模型 JSON 中查询。

跨域与缓存

        
GitHub Pages 默认为所有文件返回 Access-Control-Allow-Origin: *，因此任意网页都可以直接 fetch 这些 JSON，无需代理、无需 _headers 配置（GitHub Pages 也不支持自定义响应头）。

        
GitHub Pages 会对文件设置约 10 分钟的 CDN 缓存（Cache-Control: max-age=600），数据更新后可能需要稍等片刻。客户端可核对 meta.updated_at 和 meta.data_version 判断数据日期和快照是否一致。

      


      

        
数据更新（维护者）

        
接口文件由 scripts/build_api.py 从 data/prices.json 生成，修改数据后务必重新生成：

        
.venv/bin/python scripts/build_api.py      # 重新生成 api/v1/
.venv/bin/python scripts/validate.py       # 校验数据，并检查 api/v1/ 与数据是否同步

        
生成结果是确定性的（不含生成时间戳），validate.py 会逐个比对文件，发现缺失、过期或多余文件即报错。
